# Last Frame

Last Frame is a film and TV discovery web app. You can browse trending and popular titles,
open a title for details, and keep a watchlist, history and ratings for each profile. It is a single-page app (Vite + React 18 +
TypeScript) styled with plain CSS in a **glass-motion** design language: translucent,
blurred panels over a dark cinematic background, with motion that switches off under
`prefers-reduced-motion`.

## Features

- **Home**: a rotating hero and horizontally scrolling rows (trending, popular TV, new
  releases, sci-fi). Rows are keyboard navigable with the arrow keys.
- **Detail dialog**: synopsis, genres, runtime, rating and match score. The dialog is
  focus-trapped and closes with `Esc`.
- **Routes** for title pages, search, genres, My List, profiles, account and plans. Some of
  these are still placeholder pages that other streams are filling in.
- **User state**: profiles, watchlist, history and ratings live in a zustand store that
  persists to `localStorage` and falls back to memory when storage is unavailable.
- **Billing is mock-only**: there is no real payment processing and no Stripe SDK or keys.
- **Resilience**: route and in-layout error boundaries with a retry card, an offline banner,
  and fetch retry with exponential backoff for live adapters.
- **Brand kit** at `/brand`: four logo directions and four colourways to compare, with logo
  use, typography, colour tokens, treatments, mockups and downloadable SVGs. The choice is in
  the URL (`/brand?option=strip&colour=lagoon`), so a combination can be shared for review.
- **Brand, SEO and accessibility**: an "LF" glass monogram, SVG/PNG favicons, per-page
  `<title>` and OpenGraph/Twitter meta, `robots.txt` and `sitemap.xml`, a skip link, ARIA
  landmarks and a target of WCAG 2.2 AA (see [docs/A11Y.md](docs/A11Y.md)).
- **Mobile first**: the layout works down to 375px wide.

## Mock mode

With **no environment variables set, the whole app runs on mock adapters**: a built-in
catalogue for TMDB, in-memory auth and database, mock billing and console/no-op analytics.
You don't need an account or API key to run, test or deploy a preview.

Each live integration switches on independently when its variables are present. `services.mode`
(from `src/services`) reports which adapters are live. Every variable is documented in
[docs/KEYS.md](docs/KEYS.md).

## Run locally

Requirements: Node.js 20+ and npm.

```bash
npm ci            # install exact dependencies from package-lock.json
npm run dev       # start Vite on http://localhost:5173
```

Other scripts:

| Command                | What it does                                 |
| ---------------------- | -------------------------------------------- |
| `npm run build`        | Type-check (`tsc -b`) and build into `dist/` |
| `npm run preview`      | Serve the production build locally           |
| `npm run format`       | Format the repo with Prettier                |
| `npm run format:check` | Check formatting without writing             |

To try live services locally, put the `VITE_*` variables you need in a `.env.local` file,
which Vite loads automatically. `.gitignore` doesn't list it yet, so never `git add` it. See [docs/KEYS.md](docs/KEYS.md).

## Checks

These four must pass before any change is merged. CI (`.github/workflows/ci.yml`) runs them
on every push and pull request:

```bash
npm run lint       # ESLint
npm run typecheck  # tsc -b
npm test           # Vitest (jsdom + Testing Library)
npm run build      # tsc -b && vite build
```

`tsconfig.tsbuildinfo` is generated by `tsc -b`. Discard changes to it before committing
(`git checkout -- tsconfig.tsbuildinfo`).

## Deploy to Netlify

The repo is ready for Netlify. `netlify.toml` sets the build, the functions directory, the SPA
fallback, the `/api/*` rewrite to functions, and security headers (CSP, HSTS and others).

1. In Netlify, **Add new site → Import an existing project** and pick this repository.
2. Netlify reads `netlify.toml`, so the build settings are already filled in:
   - Build command: `npm run build`
   - Publish directory: `dist`
   - Functions directory: `netlify/functions`
3. Deploy. With no environment variables the site runs in mock mode.
4. Optional: to go live, add variables under **Site configuration → Environment variables**
   (see [docs/KEYS.md](docs/KEYS.md)) and trigger a new deploy. `VITE_*` values are baked in
   at build time, so a redeploy is needed after changing them.

Serverless functions are served at `/.netlify/functions/<name>` and, through the rewrite, at
`/api/<name>`. For example, `/api/health` returns `{"ok": true}`.

If a live integration calls a new origin, add that origin to the `Content-Security-Policy`
header in `netlify.toml` (for example, `connect-src` for an analytics or Supabase host).

## Security rules

- The client only receives public values (`VITE_*`). Server secrets such as `TMDB_API_KEY`
  live in Netlify functions only.
- Billing is mock-only: no Stripe SDK and no Stripe keys, ever.
- No `innerHTML`, `dangerouslySetInnerHTML`, `eval` or `new Function`.
- Any SQL (Supabase) must ship with Row Level Security policies.
