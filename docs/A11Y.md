# Accessibility

Target: WCAG 2.2 AA. This file records what the app does, the reusable pieces, and the
numbers behind the contrast decisions. Keep it current when you touch any of these areas.

## Keyboard map

| Where         | Keys                  | Behaviour                                                                                                                 |
| ------------- | --------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| Anywhere      | `Tab` (first press)   | Reveals the **Skip to content** link; `Enter` moves focus to `#main`.                                                     |
| Row of cards  | `Tab`                 | The whole row is **one** tab stop (roving tabindex): Tab enters on the last-focused card and the next Tab leaves the row. |
| Row of cards  | `←` / `→`             | Previous / next card (stops at the ends, no wrap). Focus scrolls the card into view.                                      |
| Row of cards  | `Home` / `End`        | First / last card.                                                                                                        |
| Row of cards  | `Enter` / `Space`     | Opens the detail dialog.                                                                                                  |
| Detail dialog | `Tab` / `Shift+Tab`   | Cycles inside the dialog only (focus trap).                                                                               |
| Detail dialog | `Esc`                 | Closes; focus returns to the card that opened it.                                                                         |
| Mobile menu   | `Esc`                 | Closes the ≤ 1024px nav menu; focus returns to the "Menu" toggle.                                                         |
| Theme control | `←` / `→` / `↑` / `↓` | Moves to and selects the previous / next of System, Light, Dark (wraps); `Home` / `End` jump. One tab stop.               |

The row's `‹ ›` scroll buttons are pointer helpers and are kept out of the tab order
(`tabIndex=-1`); keyboard users browse with arrow keys instead.

## Reusable hooks (`src/hooks/`)

### `useRovingFocus(count, { orientation?, loop?, initialIndex? })`

Returns `{ activeIndex, setActiveIndex, focusIndex, getItemProps }`. Spread
`getItemProps(i)` onto each item (it supplies `ref`, `tabIndex`, `onFocus`, `onKeyDown`).
Arrow keys follow `orientation` (`horizontal` default, `vertical`, or `both`), `Home`/`End`
jump to the ends, modifier-key combos are ignored, and the tab stop is clamped when the list
shrinks. Items must forward refs (see `MovieCard`).

### `useFocusTrap(containerRef, active, { onEscape?, initialFocus?, restoreFocus? })`

While `active`: focuses `initialFocus` (else the first tabbable element, else the container),
wraps `Tab`/`Shift+Tab` at the edges, pulls stray focus back inside, calls `onEscape` on
`Esc`, and on deactivation/unmount returns focus to whatever was focused before (default
on). `onEscape` may be an inline arrow; it is read through a ref so the trap is not torn down
on every render. `getFocusable(root)` is exported for reuse.

Use both for any new modal, menu, or card rail. Tests: `src/hooks/*.test.tsx`,
`src/components/a11y.test.tsx`.

## Landmarks, roles and names

- **Skip link** (`AppLayout`): first focusable element, `glass` styled, off-screen until
  focused, targets `#main` — a `tabIndex=-1` wrapper around the routed page. Pages keep
  rendering their own `<main>`; do not add a second `id="main"`.
- **Navigation**: `<nav aria-label="Primary">`; logo link named "Last Frame home"; search is
  `type="search"` with `aria-label="Search titles"`.
- **Mobile menu** (`Navbar`, styles in `src/styles/nav.css`): at ≤ 1024px the inline links are
  hidden and an `IconButton` named "Menu" (`aria-expanded`, `aria-controls="primary-nav-links"`)
  reveals the same `.nav-links` list as a glass dropdown (`.is-open`). `Esc` and an outside
  click close it and return focus to the toggle; choosing a link or any route change also
  closes it. The open animation is off under reduced motion. At ≤ 480px the logo shows the
  mark only (the link keeps its "Last Frame home" name) so the bar fits at 375px.
- **Rows**: `<section aria-labelledby>` the row heading (a named `region`); the card track is
  `role="group"` named after the row.
- **Cards**: accessible name is `"<title>, <year>"`; the poster `img` has `alt=""` and the
  hover info panel is `aria-hidden` so the name is not read twice.
- **Detail dialog**: `role="dialog" aria-modal="true" aria-labelledby` (the title)
  `aria-describedby` (the synopsis); close button is named "Close details".
- **Hero**: dot pager is a `group` ("Featured titles"); each dot has `aria-pressed`.
- **Icon glyphs** (`▶ ＋ ⓘ ✕ ‹ ›`) are wrapped in `aria-hidden` spans so they are not
  announced; the visible/`aria-label` text carries the meaning. The `IconButton` primitive
  already requires a `label`.
- **Toasts**: see [Toasts](#toasts-srccomponentsuitoasttsx) below.

## Toasts (`src/components/ui/Toast.tsx`)

- The fixed `.toast-region` (`role="region"`, "Notifications") holds two always-mounted,
  visually co-located stacks: a polite `role="status"` stack for `info`/`success` and an
  assertive `role="alert"` stack for `error`. Individual toasts carry **no** role, so nothing
  is nested inside another live region and nothing is announced twice. Both stacks stay in
  the DOM while empty so the first insertion is announced. Layout rules: `src/styles/toast.css`.
- **Timing (WCAG 2.2.1)**: auto-dismiss (default 4000 ms; `duration: 0` keeps the toast
  until closed) pauses while the pointer is over a toast, while focus is inside it, and
  while the tab is hidden; it resumes with the remaining time once all of those end. Every
  toast has a "Dismiss" `IconButton`.
- The exit animation is skipped under reduced motion (`matchMedia` is feature-checked).
- Tests: `src/components/ui/Toast.test.tsx`.

## Route changes (`src/components/a11y/RouteAnnouncer.tsx`)

Client-side navigation does not reload the page, so by default focus stays on the clicked
link and screen readers announce nothing. `RouteAnnouncer`, mounted once in `AppLayout`,
fixes both:

- It is an always-mounted, visually hidden (`.sr-only` in `a11y.css`)
  `role="status" aria-live="polite"` region.
- When `location.pathname` changes, it waits one tick (`setTimeout 0`) so the new page's
  `useMeta` has set `document.title`, then says **"Navigated to &lt;document.title&gt;"** and
  moves focus to `#main` (`tabIndex=-1`) with `preventScroll`, so the next `Tab` starts at
  the top of the new page.
- Nothing is announced on the first render (the browser announces the initial load).
- Hash- or search-only changes are ignored (it only watches `pathname`).
- If a modal is open (`[aria-modal="true"]`, e.g. `TrailerModal`), it still announces but does
  not move focus, so the focus trap is never broken.

Pages must call `useMeta({ title })` for the announcement to be meaningful. Routes are
`React.lazy` chunks behind Suspense, so on a first visit the title may not have changed after
one tick; in that case focus is still reset immediately, but the announcement waits (via a
`MutationObserver` on `<head>`) until the title changes, or at most `TITLE_WAIT_MS` (1.5 s),
so a stale title is never read out. Tests: `src/components/a11y/RouteAnnouncer.test.tsx`.

`.sr-only` is the shared visually-hidden utility; reuse it rather than adding new ones.

## Contrast (WCAG 2.x relative luminance)

The Lumen tokens live in `tokens.css` (light values) and `themes.css` (dark overrides). Light
is the default and follows the device; `<html data-theme="light|dark">` pins a choice
(see "Theme" below). Ratios are computed from the token values, compositing translucent layers
over the stated backdrop. AA needs 4.5:1 for body text and 3:1 for large/bold ≥ 18.66px text
and UI outlines. Every pair below passes AA in both themes unless marked.

| Foreground on background                                    | Light | Dark  | Result                                |
| ----------------------------------------------------------- | ----- | ----- | ------------------------------------- |
| `--color-text` on `--color-bg`                              | 17.1  | 17.1  | AAA                                   |
| `--color-text-soft` on `--color-bg`                         | 8.1   | 9.8   | AAA                                   |
| `--color-muted` on `--color-bg`                             | 5.3   | 6.0   | AA (body)                             |
| `--color-text` on `--color-surface`                         | 18.5  | 15.8  | AAA                                   |
| `--color-text-soft` on `--color-surface-2`                  | 7.4   | 8.2   | AAA                                   |
| `--color-muted` on `--color-surface-2`                      | 4.8   | 5.1   | AA (body), do not go lighter          |
| `--color-accent-text` on `--color-bg` (links)               | 8.3   | 9.2   | AAA                                   |
| `--color-on-accent` on `--color-accent` (buttons)           | 6.1   | 6.7   | AA                                    |
| `--color-accent` on `--color-bg` (focus ring, outlines)     | 5.7   | 6.7   | passes 3:1 non-text                   |
| `--color-success` / `--color-warn` / `--color-danger` on bg | ≥ 5.0 | ≥ 8.2 | AA                                    |
| `--color-text` on `.glass` over bg                          | 17.8  | 14.8  | AAA                                   |
| `--color-text-soft` on `.glass` over bg                     | 8.5   | 8.5   | AAA                                   |
| `--color-muted` on `.glass` over bg                         | 5.5   | 5.2   | AA (body)                             |
| `--color-text` on `--glass-bg-legible`, worst backdrop      | 14.0  | 11.5  | AAA                                   |
| `--color-text-soft` on `--glass-bg-legible`, worst backdrop | 6.7   | 6.6   | AA                                    |
| `--color-muted` on `--glass-bg-legible`, worst backdrop     | 4.3   | 4.0   | **fails body text**: never muted here |
| Lavender (light) / Violet (dark) as text on bg              | 2.6   | 3.0   | **decoration only**, never text       |
| Theme toggle: unchecked label (`text-soft` on `surface-2`)  | 7.4   | 8.2   | AAA                                   |
| Theme toggle: checked label (`text` on `control-selected`)  | 18.5  | 11.7  | AAA                                   |

The theme toggle's checked state is carried by text colour (`text` vs `text-soft`, both AAA), the
`--color-control-selected` surface and a `--glass-border-strong` hairline; in dark the surface steps
are about 1.2:1 apart and the hairline about 2.6:1 against the track, so the state never relies on
boundary contrast alone.

Worst backdrops for legible glass are pure black under the light theme (composites to about
#e0e0e0) and pure white under the dark theme (about #353244). Text-bearing glass over imagery
uses `--color-text` or `--color-text-soft` only, as before.

## Theme (System / Light / Dark)

- The choice is a device preference, saved in `localStorage` under `lf.theme` (not the synced
  store). `public/theme-init.js` runs first in `<head>`, before any stylesheet, and puts
  `data-theme` on `<html>` so a reload never flashes the other theme. With no saved choice there
  is no attribute and `themes.css` follows `prefers-color-scheme`; a device change applies live.
- `color-scheme` follows the theme, so form controls and scrollbars match. The two `theme-color`
  metas (light and dark `media`) are recoloured to the chosen theme so the browser chrome follows
  an explicit choice too.
- The control (`ThemeToggle`, `src/components/ui/`) is a `radiogroup` with one tab stop (roving
  tabindex). `←`/`→`/`↑`/`↓` move and select, wrapping at the ends; `Home`/`End` jump. The
  change is announced through a polite `role="status"` region ("Dark theme on", "Theme follows
  your device") and focus stays on the option. Desktop shows it in the header left of search
  with icon-only options (labels stay as the accessible names); at ≤ 1024px (phones and
  tablets) it is the first row of the menu sheet with 44px targets.
- Switching rides a view transition that grows the new theme as a circle from the control
  (600ms); under `prefers-reduced-motion` or without `startViewTransition` it swaps instantly.

## Reduced motion audit

`prefers-reduced-motion: reduce` is honoured by:

- `theme.css`: global kill-switch for animations/transitions; rows and cards forced visible.
- `primitives.css`: no hover lift on buttons.
- `a11y.css`: `scroll-behavior: auto` (was smooth), no skip-link slide, no focus lift on
  cards. (Aurora drift is already stopped by the theme.css kill-switch.)
- `Row`: scroll buttons use `behavior: 'auto'` instead of smooth scrolling.
- `Hero`: the 7-second auto-rotation does not start (also satisfies WCAG 2.2.2 Pause, Stop,
  Hide for these users); dots still switch manually.
- `Toast`: leaves immediately instead of animating out.
- `nav.css`: the mobile menu opens without its slide/fade animation.
- `ThemeToggle`: the theme switch skips the view transition and swaps instantly; option
  transitions are off through the theme.css kill-switch.

## Checklist for new UI

1. Icon-only control → `IconButton` (label required) or `aria-label` + `aria-hidden` glyph.
2. Lists of focusable tiles → `useRovingFocus`.
3. Overlays → `role="dialog" aria-modal aria-labelledby` + `useFocusTrap`.
4. Text over images → `--glass-bg-legible` or a scrim; check the table above.
5. Any new motion → add a `prefers-reduced-motion` override; JS motion checks `matchMedia`.
6. Check at 375px width and with keyboard only.
